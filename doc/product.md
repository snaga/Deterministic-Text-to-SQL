# 製品概要 (product.md)

## 🌟 製品の目的
従来のLLMによるText-to-SQL（プロンプトにDDLと自然言語を流し込み、SQL文字列を直接生成させる方式）は、構文エラー・存在しないテーブルやカラムの幻覚（ハルシネーション）・意図しないデカルト積（JOIN爆発）・SQLインジェクション脆弱性・1〜5秒に及ぶ長い推論レイテンシという深刻な課題を抱えていました。

本製品は、TypeSafe AIが提供するSystem 1特化型超高速判別モデル「Jev」と、型安全なSQL抽象構文木（AST）ビルダー（`sqlglot` 等）を組み合わせることで、**「ミリ秒オーダー（100ms未満）の超低遅延」「構文・スキーマ整合性の数学的保証（ハルシネーション率 0%）」「決定論的で堅牢なSQLコンパイル」** を実現する次世代Text-to-SQLエンジンおよびCLI/ライブラリです。

## 🎯 ターゲットユーザー
1. **データ分析者・BIツール利用者**: 自然言語で直感的にデータベースにクエリを投げ、曖昧さがある場合は対話的（Human-in-the-Loop）に条件を補正して即座に集計結果を得たいビジネスユーザー。
2. **エンタープライズ・データプラットフォーム開発者**: 既存の社内データウェアハウス（BigQuery, Snowflake, PostgreSQL 等）への安全な自然言語インターフェースを低コスト・高可用性で組み込みたいエンジニア。
3. **AIエージェント開発者**: エージェントのツールとして、決定論的かつ安全にSQLを発行させ、システム障害やデータ漏洩・過負荷クエリのリスクを構造的に遮断したい開発者。

## ✨ 主要機能 (Core Features)
- **オープン標準セマンティックメタデータ (Apache Ossie 準拠)**: The Apache Software Foundation (ASF) のインキュベーター標準である Apache Ossie（YAML / JSON）を外部設定仕様として全面採用。データセット、外部キーリレーション、集約メトリクス計算式、自然言語シノニム（`ai_context.synonyms`）を宣言的に定義・読み込み、コード変更なしで任意の業務ドメインに即時適応。
- **超並列スロット抽出 (Jev Parallel Slot Extraction)**: 自然言語クエリから「対象テーブル」「集約指標」「分析軸（ディメンション）」「フィルタ条件（数値・日付・ステータス等）」を複数スロットとして超低遅延（30ms以下）かつ決定論的に同時抽出。メタデータから判別 Criteria を動的に生成。
- **グラフ探索型自動JOIN解決 (FK Graph Shortest Path Resolver)**: テーブル間の外部キー（FK）関係を有向/無向グラフとして保持し、抽出されたテーブル群を結ぶ最短経路（または最小全域木近似）をミリ秒未満で決定論的に特定・自動JOIN結合。
- **型安全ASTコンパイル (`sqlglot`)**: 抽出されたスロット、Ossie 定義のメトリクス集約式、および解決済みJOINパスから、文字列連結ではなくASTノードとしてSQLを構造的にアセンブリ。構文エラーを物理的に排除し、複数ダイアレクト（PostgreSQL, BigQuery, Snowflake, DuckDB, SQLite等）への決定論的トランスパイルを保証。
- **Human-in-the-Loop (HITL) 曖昧性解決 & スラッシュ構文**: 解釈が複数に分かれる曖昧クエリ（例: 同一シノニムを持つ複数メトリクスの競合）をJevの多重選択・拮抗確率から動的に検出し、ユーザーに対話的な選択肢を提示。スラッシュ補足構文（`/ Aで` 等）による即時再実行に対応。
- **階層オントロジー縮退 (Ontology Deduplication)**: カテゴリと商品名、地域と国名など親子関係にある条件が指定された際、階層グラフ（Mathematical Subsumption）に基づいて冗長な上位条件を自動縮退し、過剰フィルタを防止。
- **ホワイトリストバインドとSQLインジェクションの構造的遮断**: 固定区分値やステータス値をChoiceプリミティブで型安全にバインドし、不正なSQL注入やハルシネーションを構造的に排除。

## 🚀 ビジネス目標 / ゴール
- **完全なスキーマ非依存・汎用化**: コードの改修を行わず、Ossie YAML を配置するだけで任意のデータベース（EC、SaaS、金融、医療など）への Text-to-SQL を稼働可能にする。
- **既存セマンティック資産とのエコシステム相互運用性**: dbt Semantic Layer や Snowflake Semantic Views、Tableau 等の既存定義を Ossie を介してシームレスに再利用可能にする。
- **レイテンシの極小化**: クエリ受付からSQL生成完了までのエンドツーエンド処理時間を 100ms 未満で完結させる。
- **ハルシネーション率 0%**: スキーマに存在しないテーブル・カラムの参照、文法エラーのあるSQLの生成を 0 件に抑え込む。
- **決定論的再現性の確立**: 同一の自然言語・メタデータ入力に対しては、100%同一のASTおよびSQLを出力し、CI/CDでの自動回帰テストを完全に成立させる。
- **APIコストの劇的削減**: 高価な汎用LLM（GPT-4やClaude 3.5 Sonnet等）を毎回呼び出すアーキテクチャに比べ、推論コストを1/10〜1/100に圧縮する。

## ⚠️ 制約事項 / スコープ外
- **汎用LLMによる複雑な自由文推論の代替**: メタデータ（辞書・スキーマ定義）に定義されていない完全未知のビジネスロジックや、数十行に及ぶプロシージャ的計算の完全自動推測はスコープ外（必要に応じて上位のLLMによる2層フォールバック構成に委ねる）。
- **非構造化データの検索**: テキスト非構造化データ（ベクトル検索など）の直接クエリは対象外とし、リレーショナルデータモデル（RDBMS / DWH）に特化する。
- **直接のDB書き込み（DDL / DML）**: データの改変・破壊を防ぐため、`SELECT` クエリの生成に特化し、`INSERT`, `UPDATE`, `DELETE`, `DROP` 等の生成は明示的に除外する。
