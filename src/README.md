# モジュール境界とアーキテクチャ方針 (L1 Intent)

本ドキュメントは、`deterministic_text_to_sql` パッケージのモジュール境界、責務、依存制約、および技術選定の理由（Why）を永続化するための仕様書（L1 Intent）です。

---

## 1. パッケージ概要

`deterministic_text_to_sql` は、TypeSafe AI の System 1 特化型高速判別モデル「Jev」と、SQL AST ビルダー「`sqlglot`」を連携させ、自然言語から高信頼・決定論的な SQL をミリ秒オーダー（<100ms）で自動合成するエンジンおよび CLI です。

LLM に直接 SQL 文字列（ブラックボックス）を生成させるのではなく、**「Jev による意図・スロットの型安全抽出」＋「セマンティックグラフによる決定論的パス探索」＋「AST コンパイル」** という明示的なコンポーネント分離を行うことで、ハルシネーションを原理的に排除します。

## 2. モジュール境界と各サブパッケージの責務

```text
src/deterministic_text_to_sql/
├── __init__.py          # パッケージルート初期化・バージョン定義
├── cli.py               # Typer / Rich による CLI エントリポイント
├── engine.py            # コア統合エンジン (DeterministicTextToSQLEngine: CLI/MCP非依存)
├── schema/              # セマンティックメタデータ管理
│   ├── models.py        # Pydantic v2 によるスキーマ・メタデータモデル
│   └── loader.py        # JSON スキーマのロード & 厳格バリデーション
├── graph/               # スキーマグラフ & JOIN 解決
│   └── resolver.py      # NetworkX による FK グラフ構築 & 最短経路 Dijkstra 探索
├── jev/                 # TypeSafe Jev API クライアント & スロット抽出
│   ├── client.py        # httpx による超低遅延 HTTP 通信 (Keep-Alive)
│   ├── slots.py         # スロット抽出・多重選択検出 (HITL判定)・Choiceバインド
│   └── prompts.py       # Jev 判別用プロンプト・抽出スキーマ定義
├── compiler/            # 型安全 AST ビルダー & オントロジー縮退
│   ├── builder.py       # sqlglot による決定論的 AST アセンブリ & トランスパイル
│   └── deduplicator.py  # 階層オントロジー（地域/国等）の冗長親条件縮退
└── hitl/                # Human-in-the-Loop 対話管理
    └── feedback.py      # スラッシュ補足構文 (/ ...) 解析 & 曖昧性対話
```

### 責務詳細

| サブモジュール | 責務 (What it does) | 扱わないこと (What it does NOT do) |
|:--------------|:-------------------|:----------------------------------|
| **`schema`** | テーブル/カラム定義、役割（id, metric, dimension, fk）、集約候補、許容値リストのデータモデル化とバリデーション | グラフ構造の探索、SQL の構文生成 |
| **`graph`** | 外部キー参照に基づくテーブル結合グラフ構築、最短経路（Dijkstra）探索、ON 条件の生成 | API 通信、AST ノードの組み立て |
| **`jev`** | Jev API（`POST /v1/systemone`）との HTTP 通信、自然言語からのスロット（テーブル/軸/指標/フィルタ）抽出、値域ホワイトリストバインド | SQL 文字列や AST の生成、CLI 入出力 |
| **`compiler`** | スロット・JOIN 条件に基づく `sqlglot` AST ノードの構築、階層オントロジー（親子条件）の縮退、ダイアレクト別トランスパイル | 自然言語の解釈、外部 API との通信 |
| **`hitl`** | 複数選択競合時の曖昧性検知、スラッシュ補足構文（`/ ...`）の解析とクエリ合成 | 実際のクエリ実行、AST 構築 |
| **`engine.py`** | パイプライン全体のオーケストレーション、CLI/MCP 双方から利用可能な高レベル API 提供 | UI 描画、ターミナル対話 |
| **`cli.py`** | コマンドライン引数処理、ターミナル描画（Rich）、エージェント向け構造化 JSON 出力（`--json`） | コアビジネスロジックの直接実装 |

## 3. 依存制約ルール (Dependency Rules)

1. **一方向パイプライン流下の維持 (単方向依存)**:
   - 依存フロー: `cli` → `engine` → (`schema`, `jev`, `graph`, `compiler`, `hitl`)
   - 下位モジュール（`schema`, `graph`, `compiler`）から上位モジュール（`engine`, `cli`）への逆方向依存は**厳格に禁止**します。
   - 循環参照は物理的に排除します。
2. **純粋関数と副作用の完全分離**:
   - `compiler` と `graph` は外部 I/O を一切持たない**純粋な決定論的ロジック**として実装します。
   - 外部通信（I/O）を行うのは `jev.client` のみとし、テスト時には `respx` 等で容易にモック可能とします。
3. **厳格な型付け (Strict Typing)**:
   - すべての公開モジュール・関数は `mypy --strict` をパスする厳格な型ヒントを義務付けます。
   - メタデータやスロット情報など、ドメイン境界を跨ぐデータ構造には Pydantic v2 モデルを採用します。

## 4. 技術選定理由 (Why)

| ライブラリ / 技術 | 選定理由 (Why) |
|:-----------------|:--------------|
| **`sqlglot` (v25+)** | 文字列テンプレート結合による SQL 生成はインジェクションや構文破綻のリスクを抱えます。`sqlglot` は堅牢な Python ネイティブ AST を提供し、PostgreSQL, DuckDB, SQLite, BigQuery, Snowflake などの複数ダイアレクトへ 100% 透過的にトランスパイル可能です。 |
| **`networkx` (v3+)** | テーブル間のリレーションシップをグラフ理論としてモデル化することで、最短結合パス探索（Dijkstra）をミリ秒オーダーで決定論的に解決できます。ハルシネーションによる誤った JOIN の発生を物理的に防ぎます。 |
| **`pydantic` (v2+)** | Rust コアにより超高速な検証性能を誇り、セマンティックメタデータの不整合を起動時・ロード時に即座に弾きます。 |
| **`httpx` (v0.27+)** | HTTP/1.1 および HTTP/2 の Keep-Alive / コネクションプールをサポートし、TypeSafe Jev API との往復レイテンシを最小化（<30ms）します。 |
| **`typer` + `rich`** | CLI において、人間向けの直感的なカラー出力・プロンプトと、AI エージェント向けの厳格な構造化 JSON 出力（`--json`）の両方をシンプルかつ美しく実現します。 |
